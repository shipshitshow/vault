# Editing, captions and broadcast

Use [identity](identity.md), [tokens](tokens.json) and [inventory](inventory.json) with the actual recording/project. This kit does not replace the selected editor, streaming tool or an existing approved motion project.

## Screen hierarchy and scenes

Faces, dialogue and readable demos take priority. Use the exact standalone six-arm asterisk, modest names and one small topic label. Edited-video signatures are white/black for contrast; live signatures are red. Use the canonical bottom-right token placement for thumbnail/slate exports; verify broadcast camera/caption/UI placement in the actual scene. No extra dot, waves or boxed mark.

At 1920×1080, start with 48 px outer clearance, the proportionally scaled 144×144 signature viewport at x1704/y864 for a 1920×1080 thumbnail/slate and a narrow partner strip only when required. These are house starting values, not platform guarantees. Check the actual camera/caption/UI and screen readability; do not copy coordinates from a board.

| Scene | Composition | Check |
| --- | --- | --- |
| Two hosts | Balanced cameras, compact names and signature | Faces stay large; no oversized header |
| Solo | Camera fills useful frame | Labels avoid face/microphone |
| Screen share | Product dominates; small host cameras alongside | Real product text readable |
| Guests | Native layout for actual source count | All active people/names preserved |
| Starting / ending / break | Full name, approved still, concise state | No invented start time/countdown |
| Partner | Supported read/demo, one CTA | Approved logo, exact URL, accurate disclosure |

If company logos and URLs stay on air, use a narrow optically balanced strip and keep captions above it. Company names in a brief are not approved logo files. Do not put a large sponsor panel on every recap/Short.

Private on-air concepts are not distributed. Build each scene from actual footage and editable layers; implement and check company-strip placement separately for every scene.

## Captions, lower thirds and motion

Keep typography/shapes native and editable. Use readable broad type, short caption groups, stable placement and a dark backing when needed. A colored word must not change meaning or become a default karaoke effect. Captions use the final timeline; verify names, numbers, qualifications and sync against the recording.

Use brief purposeful motion with legible holds and clean exits. Avoid constant movement, excessive glitching/flashing and intros that delay the useful opening. Detailed generated illustration should explain an actual spoken beat, not replace real people or facts.

Do not recolor/replace an existing stinger merely because this kit proposes a red token. Record its approved version. New motion needs frame rate, duration, codec, alpha, transition-point and playback receipts in its own manifest. Render success is not a watch/listen review.

## Files and editor handoff

Separate background, transparent overlay, mark, captions and audible media. A JPG cannot provide transparent camera windows. Never crop a board into a logo master or flatten an entire edit into one generated frame.

Use native OBS/Restream layouts/names when practical. Test exact placement in the chosen canvas. Restream graphics do not play embedded audio; an audible intro needs the appropriate media source. Recheck [graphics guidance](https://support.restream.io/en/articles/8540835-add-graphics-to-your-stream-in-studio).

Native projects, recordings and large renders stay in the media library. Record kit revision, logo hash, fonts, caption style and approved deviations with the edit. Follow [editing handoff](../production/editing-workflow.md), [overlay](https://github.com/shipshitshow/skills/tree/master/overlays) and [recap](https://github.com/shipshitshow/skills/tree/master/recap) contracts.
