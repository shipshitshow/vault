# Construct the show around a viewer decision

Hosts open Ressources/X and talk naturally. Preparation makes that conversation easier to follow; it does not provide prose to perform.

Before going live, settle one viewer question and the provisional answer the hosts can support. Select three to five source clusters. Locate the exact passage/tweet/result in advance. For each cluster record the question, primary evidence plus useful X discussion, firsthand example, disagreement/uncertainty, viewer consequence, rough time budget and exit cue.

Lead with the useful comparison or proof; insert release chronology where it explains the choice. Keep chat and tangents, but park diversions that do not answer the episode question. Hosts can disagree without manufacturing a verdict. End with the actual answer and its limits.

## Demo readiness

Check account/quota, fixture, expected result and recovery before the show. Prepare a short recorded or deterministic local demo as the fallback. If neither is ready, describe the discussion honestly rather than promising a demo. Reserve/purchase capacity only with authorization.

Move sound/image and source-window checks before the substantive opening. Start with a short cue in the host's own words. A roughly 30-second viewer promise is a pilot hypothesis, not a mandatory script or a platform guarantee.

## Practical source-board shape

Use `## Sources — <viewer question>` and `###` subheadings in app topic Markdown. Keep sources and cue bullets together. Preserve topic frontmatter. For multiple topic files, maintain a separate run-of-show note for episode order. Confirm the current renderer instead of assuming older talking-points filters.

## Review the execution

Record actual timings, unexpected tangents, demo result and unclear transitions. Compare like-for-like live and replay retention, average view duration, concurrent/return viewers, impressions, CTR and traffic. Inspect dips around setup, ads and transitions. Public cumulative views alone cannot identify a cause.

A small pilot can improve one execution variable per episode: opening, proof order, demo fallback or transitions. Retain the real operator stories and different conclusions that make this show distinctive.
